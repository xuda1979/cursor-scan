软件设计说明书

=========================================================
1  引言
=========================================================

1.1  编写目的
本说明书由 许达（中国移动研究院）编写，描述 cursor-scan 本地安全债
扫描软件 V1.0 的总体与详细设计，
作为软件实现、测试、维护及著作权登记的技术依据。读者对象为开发人员、
测试人员、维护人员与软件评审人员。

1.2  项目背景
随着大型语言模型辅助编程（vibe-code）的普及，AI 生成的代码在带来开发
效率的同时也引入了大量「安全债」：使用 MD5 弱哈希、硬编码密钥、无鉴权
路由、不安全反序列化、依赖使用已知漏洞版本等。本项目提供一个开机即用的
本地安全扫描器，对项目目录进行静态扫描，输出逐项证据（file:line + 修复
建议）、健康度评分卡（0–100 分，A–F 等级），并可作为 CI 门禁。

术语与缩略语：
  AST            抽象语法树（Abstract Syntax Tree）
  SARIF          Static Analysis Results Interchange Format 2.1.0
  CVE            公共漏洞与暴露（Common Vulnerabilities and Exposures）
  CWE            公共弱点枚举
  SAST           静态应用安全测试（Static Application Security Testing）
  FP / FN        误报（False Positive）/ 漏报（False Negative）
  tree-sitter    增量式语法解析器生成框架，用于生成精确 AST
  regex          正则表达式
  boolean 短路   条件表达式中一旦确定结果即停止求值的求值策略

=========================================================
2  总体设计
=========================================================

2.1  设计目标
(1) 检测率：对含已知安全隐患的脆弱样例项目达到 ≥90% 检出率；
(2) 零误报：对无安全问题的样例项目不产生任何发现；
(3) 可解释：评分卡每维度扣分可逐项追溯至具体证据；
(4) 可离线性：除 tree-sitter 解析库外零网络、零 GPU、零远程调用；
(5) 可扩展：规则以独立模块注册，新增维度无需改动扫描主流程。

2.2  系统总体结构
系统采用模块化分层结构，共四层：

  层1 命令行层（cli.py）       —— 参数解析、命令分发、输出渲染、门禁判定
  层2 编排层（scan.py）        —— 文件发现、文本读取、规则调度、结果汇聚
  层3 规则与扫描层（rules/、scanners/）—— 各维度检测规则与 AST 扫描器
  层4 支撑层（models / history / ignore / webapp）—— 模型、持久化、抑制、仪表板

数据流：
  用户命令行参数
    → cli 解析（argparse）
    → scan_project(target, ScanOptions)
        → 目录遍历（os.walk + 黑名单过滤）
        → 逐文件读取（二进制/超大/编码检测）
        → 语言识别（扩展名 → tree-sitter 语法）
        → AST 扫描 + 正则回退 + 秘密/依赖规则（逐文件）
        → 项目级规则（访问控制，跨文件）
        → 去重、抑制、回填代码片段
        → 评分卡计算
        → 结果序列化
    → 输出（text / JSON / SARIF）或历史快照保存
    → 门禁判定（退出码 0/1，环境错误退出码 2）

2.4  接口设计

2.4.1  用户接口（CLI）
  usage: cursor-scan [path] [--format text|json|sarif]
                     [--fail-on low|medium|high|critical]
                     [--ignore PATTERN]... [--max-bytes N]
                     [--history] [--diff BEFORE AFTER]
                     [--serve] [--host H] [--port P]
                     [--no-save] [--history-dir D] [--version]
  位置参数：
    path               待扫描项目目录（默认 "."）
  选项：
    --format           输出格式（默认 text）
    --fail-on          门禁阈值（默认 high）
    --ignore           抑制匹配的发现（可重复）
    --max-bytes        跳过超大源文件（默认 2 MiB）
    --history          列出历史快照
    --diff             比较两次快照
    --serve            启动离线仪表板（默认 127.0.0.1:8080）
    --no-save          不写入历史快照
    --history-dir      历史目录（默认 ./history）
  退出码约定：
    exit 0   扫描完成且无达到门禁阈值的发现
    exit 1   扫描完成且存在达到门禁阈值的发现
    exit 2   用法/环境错误（目录不存在、权限不足等）

2.4.2  内部接口
  scan_project(target: str, options: ScanOptions | None) -> ScanResult
  rules.<mod>.analyze_code(path: str, code: str) -> List[Evidence]
  access_control.analyze_project(files: Dict[str, List[Tuple[int,str]]],
                                 findings: List[Evidence]) -> None
  scanners.ast.analyze_python / analyze_jsts(path, src, findings) -> None
  history.save_snapshot / list_history / resolve_snapshot /
         load_snapshot / diff_snapshots
  ignore.compile_ignores(specs: List[str]) -> List[IgnorePattern]
  webapp.route(history_dir, raw_path, query) -> (status, mime, body)

2.4.3  数据交换格式（快照 JSON）
  { "tool", "target", "started_at", "duration_sec",
    "scanned_files", "skipped_files", "score", "grade",
    "summary", "dimensions", "findings": [Evidence...],
    "suppressed": [Evidence...] }
  Evidence = { "rule_id", "title", "severity", "file", "line",
               "message", "fix", "dimension", "code_snippet" }

2.4.4  SARIF 2.1.0 输出
  依据 SARIF 2.1.0 规范生成：$schema、version、runs[0].tool.driver
  （name=cursor-scan，含规则元数据 rules[]）、results[]（ruleId、level、
  message、locations[].physicalLocation.region.startLine 与 snippet、
  properties.severity/dimension/fix/title）、invocations（起止时间、
  score/grade/scanned_files）。规则级别映射：critical/high→error、
  medium→warning、low→note。

2.5  数据库设计
本软件为本地静态分析工具，不依赖任何数据库。历史快照以文本文件
（JSON）形式持久化于历史目录（默认 ./history），命名规则：
  <目标目录slug>-<UTC时间戳>.json，如 my-project-20261116-153000.json。
同一秒内多次保存时追加序号。无表结构、无索引、无访问控制层需求。

2.6  全局数据结构（内存）
  (1) ScanResult：target、findings[]、scanned_files、skipped_files、
      started_at、duration_sec、score、grade、dimensions{}
      （dimension→DimensionScore）、summary{severity→count}、suppressed[]；
  (2) Evidence：rule_id、title、severity、file、line、message、fix、
      dimension、code_snippet；
  (3) ScanOptions：max_bytes、follow_symlinks、ignore_patterns[]；
  (4) IgnorePattern：rule、file、line（三字段可选，条件匹配）；
  (5) 语言缓存与解析器缓存：模块级字典 _LANG_CACHE / _PARSER_CACHE，
      每个语言只构造一次 tree-sitter Language 与 Parser 对象。

2.7  安全设计
  (1) 扫描目标过滤：SKIP_DIRS 黑名单跳过 .git、node_modules、虚拟环境、
      __pycache__、dist 等；SKIP_EXTS 跳过二进制与打包文件；超大文件
      （>max_bytes）跳过并计数；8 KB 窗口内出现 NUL 字节判定为二进制；
  (2) 仪表板安全：快照文件名经白名单正则校验并做真实路径解析
      （os.path.realpath），拒绝越权路径（路径穿越防护）；所有输出经
      HTML 转义（html.escape）防止存储型 XSS；
  (3) 规则引擎自身防御：正则规则经 code_lines 行规约后执行，剥离
      注释/文档串，避免规则匹配到自身的模式文本；
  (4) 单文件异常隔离：单个文件 AST 解析失败仅产生 internal.scan_error
      低严重度发现，绝不让一次异常中断整次扫描。

2.8  运行设计
  (1) 启动：cli.main() 解析参数后进入对应命令分支（scan / history /
      diff / serve）；
  (2) 扫描：scan_project 同步执行；文件流按稳定顺序（排序后的目录与
      文件名）遍历，保证结果确定性；
  (3) 并发：默认单线程顺序执行（低算力守则）；Web 仪表板使用
      ThreadingHTTPServer 处理并发请求；
  (4) 终止：--serve 模式捕获 KeyboardInterrupt 后关闭服务器正常退出。

=========================================================
3  详细设计
=========================================================

3.1  cli.py 命令行模块
(1) 算法：argparse 定义位置参数 path 与全部选项；main() 依据
    args.history / args.serve / args.diff 进行命令分发；默认分支执行
    扫描、快照保存、输出渲染与门禁判定。
(2) 关键流程：
    main()
      ├─ args.history → _cmd_history()
      ├─ args.serve   → _cmd_serve()
      ├─ args.diff    → load×2 → diff_snapshots → print_diff()
      └─ 扫描
          scan_project(args.path, ScanOptions(...))
          ├─ 成功 → 可选 save_snapshot()
          │          ├─ json → result_to_dict
          │          ├─ sarif → result_to_sarif
          │          └─ text → print_text_report
          │          门禁: any(SEVERITY_ORDER[f.severity] >=
          │                  SEVERITY_ORDER[args.fail_on]) → exit 1
          │          否则 exit 0
          └─ 异常 → NotADirectoryError / PermissionError → 打印 → exit 2
(3) 关键数据结构：argparse.Namespace；result_to_sarif 内部规则去重
    字典 seen{rule_id → rule def}。
(4) SARIF 编码细节：region.snippet.text 中字面 "]]>" 按 SARIF
    附录 J 转义为 "]]]]><![CDATA[>"；severity→level 映射如 2.4.4。
(5) diff 渲染：评分 delta（正负号）、新增/修复/仍在/忽略/取消忽略
    计数与逐条行，被抑制项标注「后一次扫描中被 --ignore 抑制」。

3.2  scan.py 扫描编排模块
(1) 文件发现迭代器 _iter_source_files：
    对 os.walk 输出按目录名黑名单（SKIP_DIRS）与隐藏目录过滤，文件名
    扩展名（SKIP_EXTS）过滤，再按 ALWAYS_TEXT 清单（Dockerfile、
    requirements.txt、package.json、.env 等）或 TEXT_EXTS 扩展名判定
    是否为待扫描文本；.cursor-scan.json 配置自身不扫描。
(2) 文本读取 _read_text：
    先 os.stat 校验大小（>max_bytes → skipped），二进制嗅探（首 8 KB
    含 NUL/控制字节 → skipped），UTF-8 严格解码失败时回退 latin-1 并
    记录 encoding 状态，保证正则规则仍可执行。
(3) 单文件调度 _scan_file：
    - 识别语言 lang_for_file（扩展名→python/javascript/typescript）；
    - python → ast_scanners.analyze_python；js/ts → analyze_jsts；
      异常时记录 internal.scan_error；
    - 无条件对全部文本文件追加正则规则（crypto、injection、
      deserialization、permissions）与 secrets、deps、xss 规则。
(4) 项目级规则：缓存全部 {rel_path: [(lineno, text)]} 后调用
    access_control.analyze_project 进行跨文件鉴权分析。
(5) 去重与排序 _finalize：
    以 (rule_id, file, line) 三元组去重；按 (file, line, rule_id) 排序；
    --ignore 与配置文件模式合并后执行抑制划分（findings/suppressed）；
    统计 summary{severity:count}；调用 Scorecard.from_result 计算评分。
(6) 代码片段回填 _backfill_snippets：
    以相对路径与绝对路径双键索引各行文本，将每条发现的 code_snippet
    填充为对应行文本（strip 后），供 JSON/SARIF/仪表板统一使用。

3.3  scanners/ast.py AST 扫描器
(1) 解析器管理：模块级缓存按语言实例化 tree-sitter Language 与
    Parser（_LANG_CACHE / _PARSER_CACHE），parse(source, lang) 以
    UTF-8（errors=surrogatepass）编码解析。
(2) 语法覆盖：Python 语法节点 call；JS/TS 语法节点 call_expression。
(3) collect_calls：深度优先栈式遍历所有 call 节点；
    call_fn_name：取 function 字段字节区间还原文本（如 "hashlib.md5"、
    "yaml.load"）；args_text：取 arguments 字段文本。
(4) Python 规则分支（analyze_python），判定函数名后进入各分支：
    a. 弱哈希：hashlib.md5/sha1、bare md5/sha1、hashlib.new("md5"|"sha1")
       → crypto.md5_or_sha1（hashlib.new 形式 high，bare 形式 medium）；
    b. 弱加密算法/模式：AES/DES/DES3/TripleDES.new 等，args 含
       MODE.ECB/ECB → crypto.ecb_mode；DES* → crypto.weak_cipher_des；
       关键字参数 iv/nonce 为字面量 → crypto.fixed_iv
       （_find_kw_literal 遍历关键字参数子节点）；
    c. 硬编码种子：random.seed / np.random.seed / torch.manual_seed 等，
       首参为标量字面量（_is_literal_scalar）→ crypto.hardcoded_seed；
    d. 反序列化：pickle/cPickle.load(s) → deser.pickle（critical）；
       yaml.load 未显式省略安全 Loader 判定 _yaml_safe（仅包含
       SafeLoader 视为安全）→ deser.yaml_load；yaml.unsafe_load 直接
       标记；eval/exec/compile 且 _has_external_input（request.、input(、
       sys.argv、os.environ、.json(、.body 等特征串）→ deser.eval；
    e. 注入：*.execute 系且 _contains_sql 且 _has_concat →
       injection.sql_concat；os.system / subprocess.* 且 shell=True 且
       拼接 → injection.shell_concat；
    f. 权限：os.chmod 末参为 0o777/0o666（_is_0777/_is_0666）→
       perms.chmod_world_writable；mkdir/makedirs 0777 →
       perms.world_writable_dir。
(5) JS/TS 规则分支（analyze_jsts）：
    createHash('md5'|'sha1') → crypto.md5_or_sha1；ECB 出现在加密参数
    → crypto.ecb_mode；DES 算法 → crypto.weak_cipher_des；eval/new
    Function 且 _js_external（req./request./query./process.env 等）→
    deser.eval；数据库查询方法且 SQL 拼接 → injection.sql_concat；
    exec/spawn/execa 且 shell 或拼接 → injection.shell_concat；
    fs.chmod 0777 → perms.chmod_world_writable；writeFile 含 /tmp →
    perms.tmp_write_insecure。
(6) 辅助函数：
    _find_kw_literal(call, src, names)：定位关键字参数 iv/nonce；
    _last_arg：末参文本；_yaml_safe：SafeLoader 判定；
    _contains_sql：SQL 关键字集合；_has_concat：+ / %s 拼接特征；
    _has_external_input / _js_external：外部输入特征串集合（小写匹配）。

3.4  rules/helpers.py 行规约器
(1) 数据结构：状态机四元组 (in_triple, triple_ch, in_block)。
(2) _scan_line(raw, in_triple, triple_ch, in_block) 逐字符扫描：
    进入 /* 起始块注释、进入三引号串（docstring）、进入普通引号/反引号
    串（保留内容，仅作转义处理）、遇 # 或 // 终结行内注释；块注释与
    三引号串跨行续扫，未闭合则整行规约至行尾状态传递。
(3) code_lines(source) 产出 (lineno, reduced) 序列；reduced 命中正则
    定义特征（re.compile/match/search ...）则整行跳过（防止规则匹配
    自身模式文本）。
(4) 设计要点：保留字符串字面量内容以保证秘密值检测仍有效；剔除文档
    串以避免文书中危险关键字（DES/ECB/pickle 等）造成误报。

3.5  规则模块（rules/）
3.5.1  crypto.py
    正则集合：RE_MD5_CALL、RE_SHA1_HASH、RE_DES、RE_ECB、
    RE_HARDCODED_IV、RE_HARDCODED_SEED。逐行（code_lines 规约后）
    匹配，import/from 行直接跳过（仅绑定名字，无实际调用）。命中即
    产出对应 Evidence（dimension=crypto，弱哈希一律 high/seed medium/
    DES high/ECB high/fixed IV high）。作为 AST 之外的通用语言回退。

3.5.2  secrets.py
    规则（优先级顺序）：PEM/OpenSSH 私钥块（跨引号串行扫描 BEGIN 标记
    → secrets.private_key）；Stripe live key（sk_live_/rk_live_）→
    stripe_key；GitHub token（gh[pousr]_）→ github_token；Slack token
    （xox[baprs]-）→ slack_token；Google API key（AIza...）→
    google_api_key；AWS Access Key ID（AKIA/ASIA...）→ aws_access_key；
    通用 KEY=value 赋值：RE_GENERIC_KEY 捕获键值，STRONG_HINT_KEYS
    （api/access/secret/token/password/private/client/credential/auth/
    pem/salt/key）命中且值通过低熵/占位守卫（LOW_ENTROPY、
    PLACEHOLDER_VALUES）且长度≥10 → secrets.hardcoded_key（high）。
    设计要点：保守化（低熵与占位值排除）以控制误报。

3.5.3  deps.py
    数据结构：KNOWN_VULNS{包名小写: [(最后受影响版本, CVE, 严重度,
    说明)]}，含 flask/jinja2/django/pillow/requests/pyyaml/
    cryptography/urllib3/pyjwt/log4j/lodash/minimist/axios/moment/
    yargs-parser 共 15 项，离线静态表。
    版本比较：_ver_tuple 提取「数字点分前缀」→ int 元组；_cmp 等宽补零
    后比较，返回 -1/0/1 或 None。
    requirements*.txt：逐行解析 name op version（== 为精确），未固定
    （无版本或非 ==）→ deps.unpinned_package（low）；固定版本命中已知
    漏洞表且 ≤ 最后受影响版本 → deps.known_vulnerable。
    package.json：json.loads 解析 dependencies/devDependencies；精确
    版本（^/~/*/latest/x 及比较符开头的视为非精确）→ _exact_npm_version；
    浮动态 → unpinned_package；精确且命中漏洞 → known_vulnerable；
    行号经 _find_dep_line 二次扫描定位。malformed JSON 静默跳过。

3.5.4  deserialization.py / injection.py / permissions.py
    均为逐行正则回退模块，规则见 2.2 表：deserialization（RE_PICKLE、
    RE_YAML_UNSAFE、RE_YAML_LOAD、RE_EVAL、RE_EXEC，import 行特判）。
    injection 覆盖 28 种语言后缀（py/js/php/java/ruby/go/cs/kt/rs/pl/
    lua/cpp/swift/sh/r/ps1/sql/vb/scala/groovy/dart/m/ex/erl/jl/hs/clj/
    fs），按语言分类的拼接模式逐一匹配：SQL 拼接（RE_SQL_CONCAT_*，
    含 +、字符串插值 $、${}、#{}、%~、printf/format、sprintf、fmt.Printf、
    str/format 等各语言特有写法，以及 Python f-string 赋值/调用
    RE_SQL_FSTRING_ASSIGN/CALL 与 RE_SQL_FMT_ASSIGN）、shell 拼接
    （RE_SHELL_CONCAT_*，含反引号命令替换与管道拼接）、RE_DANGEROUS_SHELL
    （shell=True / Process.Start / os:cmd / Cmd 等危险执行）；匹配时先经
    helpers.code_lines 规约（剔除注释与三引号内容），并将正则模式文本本身
    排除于命中之外。permissions（RE_CHMOD_0777、RE_MKDIR_WORLD、
    RE_TMP_WRITE）。命中产出 dimension=dims 的 Evidence。与 AST 双层覆盖：
    AST 给 Python/JS/TS 语言内精确节点，正则在其余语言兜底。

3.5.5  access_control.py 项目级规则
    (1) 输入：全项目 {rel_path: [(lineno, text)]}。
    (2) 第一步（项目级开关）：扫描全部文件是否出现 AUTH_INDICATORS 中
        任一鉴权特征（login_required、jwt_required、authorize、passport
        等）。全项目无任何鉴权特征则直接返回（避免纯脚本项目大量误报）。
    (3) 第二步 _flag_python：逐行命中 ROUTE_DECORATOR
        （@(app|bp|router)\.(route|get|post|put|delete|patch)）后，向
        上/下双向收集连续 @ 装饰器块（lo..hi），将整块文本拼接，若不含
        _AUTH_DECORATORS（login_required、jwt_required、auth_required、
        require_auth、token_required、permission_required、
        role_required、admin_required）中任一 @名称 正则 → 报
        access_control.missing_auth（high）。装饰器块内任一行有解析名即
        视为安全，认证装饰器位于路由装饰器下方（Flask 惯例）可正确识别。
    (4) 第三步 _flag_js：命中 EXPRESS_ROUTE（app.get/post/...）或
        FASTAPI_ROUTE 且行内无 authMiddleware/requireAuth/jsonwebtoken
        等鉴权记号 → 报 access_control.missing_auth。

3.5.6  xss.py
    规则（逐行正则）：RE_DOM_SINK（.innerHTML|insertAdjacentHTML|
    outerHTML 后跟 =( 的写形式）→ xss.dom_manipulation（medium）；
    RE_DANGEROUS_REACT（dangerouslySetInnerHTML）→ xss.dangerous_react；
    RE_DOCUMENT_WRITE（document.write(ln) 参数非纯字面量，负向前瞻排除
    "…" 单字面量")与 RE_DOC_TEMPLATE_INTERP（反引号含 ${）→
    xss.document_write；RE_TEMPLATE_RENDER（render_template_string、
    Markup）→ xss.template_render（high）；RE_AUTOESCAPE_OFF
    （{% autoescape false %} / |safe）→ xss.template_render。
    import 行跳过。安全性：只对 sink 本身提醒，不追踪数据流（SAST
    全量数据流不在本项目范围）。

3.6  models.py 数据模型
    (1) Evidence：rule_id/title/severity/file/line/message/fix/
        dimension/code_snippet，dataclass 结构；
    (2) ScanResult：目标与统计字段 + add() 方法 + scorecard() 方法；
    (3) DimensionScore：维度名、score、findings[]，count 属性；
    (4) Scorecard.compute：字典 dim_map 按 DIMENSIONS 初始化 100 分，
        对每条发现 ds.score = max(0, ds.score - 权重(severity))，
        权重表 {low:5, medium:12, high:20, critical:30}；
    (5) Scorecard.grade_overall：总分取各维度均值整数，等级映射
        A≥90 / B≥75 / C≥60 / D≥40 / F<40；
    (6) SEVERITY_ORDER = {low:1, medium:2, high:3, critical:4} 供门禁与
        排序统一使用。

3.7  history.py 历史与差异
    (1) 序列化：evidence_to_dict / result_to_dict 为唯一快照结构来源
        （single source of truth），供 CLI JSON 输出与快照共用；
    (2) 保存：save_snapshot 建目录（makedirs exist_ok）、命名
        snapshot_path（slug + UTC 时间戳 %Y%m%d-%H%M%S，冲突追加 -2/-3）、
        json.dump(ensure_ascii=False, indent=2)；
    (3) 列表：list_history 通配 *.json 载入，坏文件跳过，按文件 mtime+
        started_at 倒序（最新在前）返回 HistoryEntry 列表；
    (4) 解析：resolve_snapshot 支持直接文件路径或 slug/前缀，返回最新
        匹配快照路径，无匹配抛 FileNotFoundError；
    (5) 差异 diff_snapshots：以 _finding_key=(rule_id, normpath(file),
        line) 建四组索引（before/after/after_suppressed/
        before_suppressed）；分类逻辑：
        - suppressed：before 有且 after 中被抑制（且不再 active）；
        - fixed：before 有，after 无且未被抑制；
        - unsuppressed：before 中被抑制、after 重新 active；
        - added：after 新增且非 unsuppressed；
        - kept：前后共有。
      差异语义保证「忽略 ≠ 修复」。

3.8  ignore.py 抑制机制
    IgnorePattern 三字段（rule/file/line 均可选）。解析：':' 分隔补足
    三位，空段视为省略。匹配：单字段模式（file/line 均无）→ 规则号 /
    文件名 basename / 相对路径任一命中即匹配；多字段模式 → 各字段逐一
    fnmatchcase 匹配并组合（line 字段需精确相等）。compile_ignores 批量
    编译；is_suppressed 为便捷封装。

3.9  webapp.py 离线仪表板
    (1) 路由 route(history_dir, raw_path, query)：纯函数分发，返回
        (status, mime, body)，同时被 HTTP 处理器与测试直接复用；
        路径表：/（索引）、/api/history.json、/api/snapshot/<name>、
        /snapshot/<name>、/diff?before=&after=，其余 404；
    (2) 安全：_safe_snapshot_path 对 name 做字符白名单
        （[A-Za-z0-9._-]+），realpath 后校验候选路径必须落在
        history_dir 前缀内（防目录穿越）；resolve_snapshot 兜底；
    (3) 渲染：_page 拼装 HTML + 内联 CSS（_PAGE_CSS）；_e 统一
        html.escape（quote=True）防 XSS；_findings_table 按严重度行、
        含代码片段 <pre>；色彩按 grade 映射 grade-a..f；
    (4) 页面：索引列出全部快照并提供前后两次比较表单；快照页展示评分
        头、维度评分与逐项证据、已忽略列表；差异页展示评分 delta 与
        新增/修复/忽略/取消忽略/仍在分区（<details> 折叠）；
    (5) HTTP 层：ThreadingHTTPServer + BaseHTTPRequestHandler 子类
        DashboardHandler（history_dir 注入），GET/HEAD 支持，输出带
        X-Content-Type-Options: nosniff，log_message 静默。

3.10 关键算法复杂度
    全部规则为逐行（或遍历 AST 节点）的一次性扫描：
    文本行规则 O(行数×正则集合大小)；AST 扫描 O(节点数)；项目级
    访问控制 O(文件数×行数)。去重 O(F log F)（排序）。评分 O(F)。
    整体可在秒级完成中小型项目扫描，满足低算力守则。
